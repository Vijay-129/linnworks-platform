# linnworks-platform MCP server

Local, read-only MCP server over everything in `references/` and
`migration/STATUS.md`. Any MCP-compatible AI can query the Linnworks API and macro
integration knowledge directly instead of it being pasted into a system prompt or
knowledge upload - this is the "works in every AI" piece of the platform.

It never calls the real Linnworks API - it only reads local markdown generated by
`scripts/sync_api_spec.py`, `scripts/sync_macro_integrations.py`, and the port/generate
scripts. Re-run those to keep this server's answers current; this server itself has
nothing to refresh.

## Setup

```
pip install -r requirements.txt
```

## Run (stdio, for Claude Desktop / Cursor / Antigravity / VS Code Copilot)

```
python server.py
```

Add to your client's MCP config, e.g. Claude Desktop's `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "linnworks-platform": {
      "command": "python",
      "args": ["C:\\path\\to\\linnworks-platform\\mcp-server\\server.py"]
    }
  }
}
```

## Tools

| Tool | Purpose |
|---|---|
| `list_controllers(status?)` | Every controller + migration status, optionally filtered |
| `get_endpoint(controller, version?)` | Full endpoint reference for one controller |
| `search_api(query, version?)` | Full-text search across all controller docs |
| `get_model(name, version?)` | One model's field table, wherever it's referenced from |
| `get_macro_calling_guide()` | How to reach LinnworksAPI from a macro - inside Linnworks' macro engine vs standalone code, session lifetime, error handling |
| `get_macro_integration(category)` | FTP/FTPS/SFTP/Email/Dropbox/raw-HTTP contract + real code |
| `list_macro_patterns()` | Hand-written macro gotchas/patterns available |
| `get_macro_pattern(name)` | Read one pattern doc |
| `get_standards()` | Coding conventions generated code should follow (SDK layer) |
| `get_macro_conventions()` | Macro-authoring rules: structure, start/end logging, human-readable IDs, mandatory rate-limit-safe API wrapper (with code template), server-side filter selection, idempotency |
| `list_golden_examples()` | List real approved macros kept as reference examples |
| `get_golden_example(name)` | Read one golden example macro's full source |
| `get_golden_example_notes()` | What to copy vs fix in each golden example - none are fully compliant with `get_macro_conventions()` |
| `check_against_standards(code)` | Lint a C# snippet against the mechanically-checkable rules (nullable reference types, missing StringEnumConverter, interface naming, SDK-layer logging, empty catches, async usage) |

`check_against_standards` is a regex linter, not a compiler - it only covers rules
that are checkable from a single snippet with no cross-file context (it can't verify
e.g. a Models/ file's name matches its class, or that a request/response model
inherits `LinnObject`). Read `get_standards()` for the full rule set; a clean lint
result is not proof the code is correct.
